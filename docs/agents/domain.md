# Domain docs

This application uses a single context: root `CONTEXT.md` for domain vocabulary and root `docs/adr/` for architectural decisions.

Before exploring a domain topic, read `CONTEXT.md` and relevant ADRs. If a context document is absent, proceed silently. Use glossary terms in issues, models, tests, and explanations; flag a real vocabulary gap for domain modeling rather than inventing synonyms.

Flag output that contradicts an ADR, identify the record, and explain why reopening it may be warranted. Keep `CONTEXT.md` a glossary; product requirements belong in `PRODUCT.md`, and investigation belongs under `docs/research/`.
